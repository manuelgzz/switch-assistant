# Switch Assistant v1.12.1

Esta versión consolida el desarrollo del fork `manuelgzz/switch-assistant` hasta **1.12.1-fix6**. Amplía la integración con Home Assistant y reúne las correcciones de audio, detección de juegos, catálogo de títulos y conservación de lecturas MQTT.

## Controles de Home Assistant

| Control | Comportamiento |
| --- | --- |
| **Brightness control** | Permite ajustar el brillo entre 0 y 100 %. Conserva el sensor de brillo de lectura. |
| **Screen** | Enciende o apaga la retroiluminación. Su nombre visible reemplaza a **Screen control**; conserva su identificador MQTT. Apagar la pantalla no solicita suspender la consola. |
| **Volume control** | Permite ajustar el volumen entre 0 y 100 % usando la salida de audio disponible. |
| **Volume up / Volume down** | Ajusta el volumen por pasos adaptados a la escala del hardware. Evita que un incremento pequeño se trunque a cero. |
| **Mute** | Usa mute nativo cuando está disponible. Como alternativa, baja el volumen a cero y permite restaurar el valor guardado durante esa ejecución. |
| **Refresh sensors** | Solicita actualizar los sensores. |
| **Fetch diagnostics** | Publica un resumen de diagnóstico y una selección acotada de mensajes técnicos. |
| **Refresh installed games** | Consulta el catálogo instalado y actualiza sus listas y contadores. |

Se conservan los botones **Reboot** y **Shutdown**, sujetos a la disponibilidad del servicio de energía correspondiente.

### Correcciones de audio

- Los sensores de lectura y los controles comparten la misma lógica de selección de salida.
- Si la consulta de salida activa falla, se intenta la salida predeterminada.
- Se utiliza volumen master como alternativa cuando la ruta de volumen por salida no está disponible o falla su escritura.
- Los valores numéricos se validan y se convierten a pasos reales del dispositivo.
- Repetir mute no sobrescribe el valor que debe restaurarse.
- **Last command result** publica el resultado y código de error de la operación. La compatibilidad depende de la salida de audio y de los servicios disponibles en cada consola.

## Sensores y diagnóstico

Se conservan los sensores existentes de batería, carga, voltaje, temperatura y salud de batería; brillo, pantalla, volumen y salida de audio; juego actual, mandos y espacio SD libre/usado.

La integración se amplía con:

| Grupo | Datos |
| --- | --- |
| **Sistema** | Tiempo encendido, temperatura interna y memoria usada por el proceso del sysmodule. |
| **MQTT** | Reconexiones, duración de la sesión, resultado del último comando y diagnóstico. |
| **Red** | Tipo de conexión y señal Wi-Fi en la escala nativa de **0 a 3 barras**. No se etiqueta como RSSI en dBm. |
| **Almacenamiento** | Capacidad total de la SD y espacio libre/total del almacenamiento interno. |
| **Mandos** | Conexión por cable y nivel de batería para hasta ocho jugadores, además de los sensores existentes de tipo y cantidad. |
| **Juego** | Nombre, Title ID, estado de ejecución, duración de la sesión observada y diagnóstico de detección. |
| **Modo de operación** | Dock, portátil y Sleep, con un diagnóstico que indica el origen del estado. |
| **RTSP** | Estado del servidor/captura, clientes conectados y resultado de inicio de captura. Se conserva la URL del stream. |

### Unidades y alcance de las lecturas

- **Sysmodule memory** mide la memoria del proceso en MiB; no representa toda la RAM de la consola.
- La batería de mandos usa la escala nativa **0–4**, no porcentajes. Para un par de Joy-Con se publica el menor nivel de los dos.
- La duración de la sesión de juego empieza cuando este proceso detecta el título. No constituye un historial persistente ni se atribuye a un usuario de Nintendo.
- Los sensores extendidos se consultan normalmente cada cinco segundos.
- El diagnóstico evita exportar configuración, tokens, contraseñas y texto de notificaciones. No equivale a descargar todos los archivos de logs.

## Detección de juegos y reparación del catálogo

La detección consulta directamente el **proceso de aplicación**, obtiene su PID y resuelve el Title ID. El catálogo local se usa para obtener el nombre; un título ausente del catálogo puede seguir reportándose como juego activo.

Se corrigió un desfase entre `titles.txt` y `titles.idx`: el índice podía apuntar a posiciones calculadas con finales de línea diferentes. Esto producía `Unknown game` incluso para títulos incluidos en la lista.

Esta versión:

- Regenera el índice a partir de los bytes reales del archivo de títulos.
- Conserva los finales de línea del catálogo en Git.
- Regenera y comprueba el índice durante la compilación en Actions.
- Incluye una búsqueda de recuperación si una entrada del índice instalado apunta a una posición incorrecta.
- Verifica el caso **`01006A800016E000` → Super Smash Bros.™ Ultimate**.

**Game detection diagnostic** muestra el método de detección o el error de consulta. El sensor Title ID conserva su identificador y formato.

### Catálogo instalado y multijugador

El escaneo es bajo demanda mediante **Refresh installed games**, con un límite de **128 registros**. La capacidad multijugador se configura en:

```text
sdmc:/switch/switch-ha/game-players.ini
```

Ejemplo:

```ini
01006A800016E000=8
```

Los metadatos permiten generar grupos y contadores para juegos de **2+, 4+ y 8 jugadores**. Los títulos sin capacidad configurada permanecen en la lista general.

**El lanzamiento de juegos desde el sysmodule no está habilitado.** Los selectores que requieren un contexto de applet compatible no están disponibles en ese contexto; consultar el catálogo no implica poder iniciar juegos desde Home Assistant.

## Suspensión, disponibilidad y valores retenidos

Los sensores y sensores binarios conservan su **última lectura retenida** al suspenderse la consola o perderse la conexión MQTT. Las lecturas conservadas no son mediciones nuevas mientras la consola duerme.

Los controles sí dependen de la conexión y, cuando corresponde, de sus servicios asociados, por lo que quedan no disponibles al desconectarse el cliente.

### Cómo se obtiene Sleep en esta versión

`Operation Mode` utiliza el estado JSON retenido de MQTT. Al perderse la conexión, el último testamento del cliente publica:

```json
{
  "status": "offline",
  "operation_mode": "Sleep",
  "mode_source": "mqtt_disconnect"
}
```

- **Sleep es una inferencia de desconexión**, no una confirmación directa del estado de energía.
- Una caída de red también puede mostrar Sleep.
- Con keepalive de 30 segundos, el broker normalmente detecta el silencio en unos **45 segundos desde el último paquete**.
- **Power state source** indica `live` para el estado publicado en línea o `mqtt_disconnect` para la inferencia.
- Al reconectar, se actualizan el estado y las lecturas.

Se retiró el listener que registraba el sysmodule en `psc:m` después del fallo reportado durante la suspensión. La versión publicada no participa en ese protocolo ni espera confirmaciones del gestor de energía.

## Overlay y acciones rápidas

Se conservan las notificaciones emergentes y se añade un menú de cuatro acciones:

- **ZL + ZR + Minus:** abrir/cerrar el menú.
- **Arriba/abajo:** seleccionar una acción.
- **A:** ejecutar.
- **B:** cerrar.

Los nombres se configuran en `sdmc:/switch/switch-ha/quick-actions.ini`:

```ini
1=Modo de juego
2=Encender escritorio
3=Atenuar luces
4=Apagar luces
```

El overlay publica los eventos `quick_action_1` a `quick_action_4` mediante **Overlay action**. Deben vincularse a automatizaciones de Home Assistant para ejecutar las escenas o servicios deseados.

El overlay no bloquea la entrada del juego. La cola de archivo admite una acción pendiente; no es una cola duradera de múltiples eventos.

## Cambios MQTT y migración de automatizaciones

Los comandos se separan por consola. Cada Switch debe usar un **Client ID diferente**.

Las automatizaciones manuales deben cambiar el antiguo topic compartido:

```text
<discovery_prefix>/command
```

por:

```text
switch_ha/<client_id_sanitizado>/command
```

La sanitización conserva caracteres alfanuméricos y reemplaza otros caracteres por `_`. Los controles individuales usan:

```text
switch_ha/<client_id_sanitizado>/control/<control>
```

Ejemplos de controles: `set_brightness`, `set_volume`, `screen`, `mute`, `volume_up` y `volume_down`.

- Los comandos y acciones deben enviarse **sin retención**. Los comandos retenidos se rechazan.
- Los estados y las configuraciones de discovery se retienen.
- Se corrigió la recepción de paquetes MQTT fragmentados o agrupados en TCP y se añadieron confirmaciones de recepción QoS 1.
- Los sensores y controles existentes conservan sus identificadores salvo los elementos retirados expresamente.
- El discovery elimina las configuraciones retenidas de los controles deshabilitados al reconectar el sysmodule actualizado.

## Funciones retiradas o pendientes

- **Sleep remoto:** retirado después del fallo reportado; sus comandos no ejecutan llamadas de suspensión.
- **Close Game:** retirado porque la terminación forzada podía mostrar que el juego se cerró a causa de un error. El cierre normal desde el sysmodule queda pendiente.
- **Interruptor RTSP de Home Assistant:** retirado. Se conserva el streaming que se habilita desde la aplicación; su activación requiere reiniciar.
- **Power event listener / participación PSC:** retirados. Se utiliza la inferencia MQTT descrita arriba.
- No se incluyen Daybreak, actualizaciones automáticas de firmware/Atmosphere ni lanzamiento de juegos en segundo plano.

## Compilación y validación

- Compilación automática para cada push a una rama y para las etiquetas de release.
- Imagen devkitPro fijada por digest para mantener el mismo toolchain.
- Construcción del sysmodule, overlay, overlay loader y aplicación NRO con sus componentes incrustados.
- Pruebas de host para discovery JSON, aislamiento entre consolas, comandos retenidos, paquetes MQTT, audio, detección de juegos, inicialización de firmware e índice de títulos.
- Validación de los mensajes de último testamento y reconexión usados por el modo de operación.

La compilación y las pruebas de host pasaron para el release. No sustituyen la validación física de todos los servicios, salidas de audio y ciclos de suspensión/reanudación en cada consola.

## Instalación o actualización

1. Descarga **`switch-ha.nro`** de los archivos de este release.
2. Sustituye `sdmc:/switch/switch-ha/switch-ha.nro`.
3. **Abre Switch Assistant** para instalar el sysmodule, overlay, loader y catálogo incrustados.
4. **Reinicia completamente la consola.** Copiar el NRO no reemplaza el proceso que ya está ejecutándose.
5. Espera la reconexión MQTT para aplicar los cambios de discovery en Home Assistant.
6. Actualiza los topics de las automatizaciones manuales si utilizaban el comando compartido anterior.

La configuración habitual sigue en `sdmc:/switch/switch-ha/config.ini`. Los controles retirados se limpian mediante discovery; si una entidad conserva un nombre personalizado en Home Assistant, ese nombre puede requerir un ajuste manual.

**Documentación:** [guía de controles, configuración y límites](https://github.com/manuelgzz/switch-assistant/blob/v1.12.1/docs/home-assistant-controls.md).
